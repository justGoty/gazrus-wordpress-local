# Подготовка и приемка рекламы Газруса

Обновлено 16.09.2026. Текущий этап: подготовка ограниченного поискового теста в Директ Про. Оплата, модерация и показы не выполнены. Публикация этого документа в Git не запускает рекламу.

## Что меняется относительно прежнего плана

Предыдущие материалы [Яндекс Бизнес](YANDEX_BUSINESS_LAUNCH.md) и [варианты текстов](YANDEX_BUSINESS_COPY.md) остаются справочными, но не являются текущей инструкцией платного запуска. Владелец ранее разрешил переход в Директ Про; он доступен. Существующие профили других сайтов не изменять.

Опыт подготовки МэтрисЛаб использован как метод работы, не как доказательство успешной рекламной кампании. Для Газруса продаем приборы, а не услуги поверки. Не копировать чужие счетчики, ID объявлений, условия, отрицательные ключевые слова и географию обслуживания.

## Единый порядок

1. Подтвердить возможность заказа выбранных моделей. Одно модельное предложение ведет на соответствующую товарную страницу, не на общую главную или библиотеку документов.
2. Подготовить варианты заголовков, текстов, коммерческих запросов и быстрых ссылок. Для каждого обещания иметь подтверждение. Первый ответ в течение суток не означает готовое КП за сутки.
3. Проверить ограничения текста, отсутствие дублей и конфликтов минус-фраз. Не исключать покупку, цену и поставку. Слова «поверка» и «сертификат» сами по себе не делают закупочный запрос нецелевым.
4. Проверить опубликованные страницы и мобильные формы отдельно от локальных данных. HTTP 200 и наличие товара не доказывают доставку обращений.
5. Проверить счетчик и цели по [METRIKA_SETUP.md](../../web/METRIKA_SETUP.md). Основные события: `lead_email_success`, `lead_callback_success`; `phone_click` не равно состоявшемуся звонку. Реальные тестовые обращения отправлять после разрешения владельца.
6. В редакторе выбрать нужные места показа и проверить все автоматические расширения. Значения по умолчанию не считать согласованными. Для формата с обязательной числовой ценой не выдумывать цену вместо запроса КП.
7. Сохранить черновик и заново проверить его ID, назначение каждой ссылки, контакты, тексты и настройки. Надпись «Черновик Новая кампания» без сохраненного ID не подтверждает сохранение.
8. Перед оплатой согласовать общую стоимость с налогами, период, географию, условия повторных списаний и запуск. Не принимать оферту и не включать показы в рамках одной лишь подготовки.
9. После разрешенного запуска считать квалифицированные обращения, КП и заказы. Расход без целевых обращений не записывать как нулевой CPL. Не повышать бюджет автоматически по числу кликов.

## Разделение данных

Публичный Git содержит только этот порядок и обезличенный журнал. Рабочие бюджеты, семантика, гипотезы и состояние аккаунта хранятся в игнорируемой папке `output/advertising/2026-09-16/`. Не публиковать ее через `git add -f`; для передачи коллеге использовать закрытый канал. Отсутствие этой папки в свежем клоне нормально.

В закрытом пакете: `README.md`, `search-campaign.json`, проверочный `verify.mjs`, отчеты и `ACCOUNT_STATUS.md`. JSON и CSV являются рабочими материалами, не официальным форматом импорта Директа. Генерируемый HTML служит листом согласования, не точным макетом рекламной выдачи.

Различать четыре независимых факта: подготовлено локально; сохранено в кабинете; принято модерацией; запущено с разрешения. Фиксировать только подтвержденный этап. Пароли, платежные данные и персональные данные клиентов не записывать ни в открытый, ни в рабочий рекламный пакет.
