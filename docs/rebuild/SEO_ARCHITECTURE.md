# SEO-архитектура

## Принцип

WordPress не обязателен. Нужны серверный HTML, стабильные URL, обычные ссылки, управляемые canonical и полезные страницы. Фильтры и SEO-посадочные — разные сущности.

## Структура

- /catalog
  - /catalog/stationary
  - /catalog/portable
  - /catalog/sensors
- /catalog/{category}/{slug}
- /gases
  - /gases/{gas}
- /solutions
  - /solutions/{task}
- /industries
  - /industries/{industry}
- /brands
  - /brands/{brand}
- /services
  - /services/supply
  - /services/verification
  - /services/calibration
  - /services/repair
- /knowledge
- /calculators
  - /calculators/gas-converter

Диапазон, канальность, IP/Ex, интерфейсы и температура по умолчанию являются фильтрами. Отдельная посадочная появляется только при подтвержденном спросе, устойчивом ассортименте и уникальном содержании.

## Страницы и метаданные

- Каноническая постраничная карта хранится в `web/content/seo/pages.json` и описана в [SEO_PAGE_MAP.md](SEO_PAGE_MAP.md).
- Динамические типы страниц хранятся в `web/content/seo/templates.json`.
- Один понятный H1.
- Уникальный title и description по реальному содержанию.
- Короткое введение перед каталогом.
- После выдачи: критерии выбора, применение, документы, FAQ и связанные решения.
- Товар: бренд, модель, газы, диапазоны, канальность, сенсор, отбор, T90, IP/Ex, интерфейсы, поверка, документы и CTA.
- Утверждения «в наличии», «официальный дилер», «собственная поверка» публикуются только после подтверждения.
- Страницы под запросы со словом «цена» честно объясняют, от каких параметров зависит стоимость, что входит в комплектацию и как получить КП; фиктивная цена не публикуется.

## Фасеты

- Индексируются только утвержденные чистые URL.
- Случайные параметры фильтров получают noindex и не входят в sitemap.
- Canonical указывает на правильную чистую страницу, но не используется для маскировки тысяч дублей.
- Пагинация имеет отдельные URL, self-canonical и обычные HTML-ссылки.
- Разрешен только реестр известных параметров; неизвестные, повторяющиеся и пустые параметры нормализуются или получают 404.
- Порядок параметров и значений канонизируется, чтобы один набор фильтров имел один URL.
- Интерфейс не создает индексируемые ссылки на все сочетания фасетов.
- Утвержденные сочетания газа, бренда и задачи ведут на чистые `/gases/`, `/brands/` и `/solutions/`, а не остаются параметрическими URL.

[Google о фасетной навигации](https://developers.google.com/crawling/docs/faceted-navigation)

## Schema.org

- Organization.
- WebSite.
- BreadcrumbList.
- Product.
- Brand.
- Service.
- ItemList.

Offer добавляется только при видимой реальной цене и доступности. Нельзя использовать цену 0 вместо «по запросу».

Для подтвержденной модели «Запросить КП» Product-разметка публикуется без Offer. Текст «цена по запросу» не подменяется фиктивным числом, а основным коммерческим действием остается форма КП.

Product без `Offer`, `review` или `aggregateRating` используется только как семантическая разметка и не претендует на товарный расширенный результат Google или Яндекса. Возможные предупреждения валидаторов документируются и не исправляются выдуманной ценой, наличием или отзывами.

- [Google Product structured data](https://developers.google.com/search/docs/appearance/structured-data/product)
- [Яндекс: товары и цены](https://yandex.ru/support/webmaster/ru/supported-schemas/goods-prices)

## Sitemap и robots

- Рабочий файл размещен в `web/public/robots.txt`; в нем нет кириллицы, CSS/JS не блокируются.
- Фасетные, поисковые, preview, draft и thank-you URL закрыты от обхода; разрешенные чистые страницы остаются доступны.
- Для Яндекса `Clean-param` применяется только к параметрам аналитики и переходным меткам, не меняющим содержание.
- Для текущего объема используется единый sitemap; разделение по товарам, категориям, услугам и материалам выполняется в P1 при росте числа URL.
- В sitemap только canonical URL с ответом 200.
- Текущий `web/src/app/sitemap.ts` включает только реализованные записи `ready/index` и опубликованные товары; planned/draft не попадают автоматически.
- Закрыть admin, внутренний поиск и технические параметры.
- Не блокировать CSS и JavaScript.
- Для Яндекса использовать `Clean-param` только для UTM и других меток, не меняющих содержание. Сортировка, режим отображения и фасеты обрабатываются правилами robots/noindex согласно [SEO_IMPLEMENTATION.md](SEO_IMPLEMENTATION.md).

## Перенос

1. Выгрузить URL из Яндекс Вебмастера, Search Console, Метрики, sitemap, логов и WordPress.
2. Сопоставить существующие `/product/{slug}/` с каноническими `/catalog/{category}/{slug}` и сохранить старый URL прямым 301 после инвентаризации.
3. Создать таблицу старый URL → новый URL → причина → статус.
4. Использовать прямые 301 без цепочек.
5. Удаленный товар вести на подтвержденную замену или близкую категорию; без аналога отдавать 404/410.
6. Не направлять все старые URL на главную.
7. Проверить status, canonical, robots, sitemap, links и schema на staging.
8. Хранить редиректы минимум год, предпочтительно постоянно.

- [Google о переносе URL](https://developers.google.com/search/docs/crawling-indexing/site-move-with-url-changes)
- [Яндекс об изменении структуры](https://yandex.ru/support/webmaster/ru/recommendations/changing-site-structure)

## Измерение

Сравнить 28 дней до запуска и 28 дней после, затем проверять еженедельно три месяца:

- индексируемые URL;
- клики, показы и позиции по кластерам;
- 404/5xx и canonical-конфликты;
- органические запросы КП;
- звонки и скачивания документов;
- использование калькулятора;
- долю небрендового трафика.
