# SEO-архитектура

## Принцип

WordPress не обязателен. Нужны серверный HTML, стабильные URL, обычные ссылки, управляемые canonical и полезные страницы. Фильтры и SEO-посадочные — разные сущности.

## Структура

- /catalog/
  - /catalog/stationary/
  - /catalog/portable/
  - /catalog/sensors/
  - /catalog/systems/
  - /catalog/accessories/
- /product/{model}/
- /gases/{gas}/
- /solutions/{task}/
- /industries/{industry}/
- /brands/{brand}/
- /services/supply/
- /services/verification/
- /services/calibration/
- /services/repair/
- /knowledge/
- /calculators/gas-converter/

Диапазон, канальность, IP/Ex, интерфейсы и температура по умолчанию являются фильтрами. Отдельная посадочная появляется только при подтвержденном спросе, устойчивом ассортименте и уникальном содержании.

## Четыре направления

| Направление | H1 | Основное содержание |
|---|---|---|
| Поставка и поверка | Поставка и поверка газоанализаторов | Подбор, комплектация, документы, схема поверки |
| Стационарные | Стационарные газоанализаторы и системы контроля загазованности | Точки, контроллеры, Ex/IP, 4–20 мА, RS-485, реле |
| Портативные | Портативные газоанализаторы для промышленной безопасности | Каналы, отбор, сигнализация, автономность, допуск |
| Сенсоры | Сенсоры для газоанализаторов | Совместимость, диапазон, технология, ресурс, калибровка |

Для поиска поставка и поверка имеют отдельные URL, несмотря на общий вход на главной.

## Страницы и метаданные

- Один понятный H1.
- Уникальный title и description по реальному содержанию.
- Короткое введение перед каталогом.
- После выдачи: критерии выбора, применение, документы, FAQ и связанные решения.
- Товар: бренд, модель, газы, диапазоны, канальность, сенсор, отбор, T90, IP/Ex, интерфейсы, поверка, документы и CTA.
- Утверждения «в наличии», «официальный дилер», «собственная поверка» публикуются только после подтверждения.

## Фасеты

- Индексируются только утвержденные чистые URL.
- Случайные параметры фильтров получают noindex и не входят в sitemap.
- Canonical указывает на правильную чистую страницу, но не используется для маскировки тысяч дублей.
- Пагинация имеет отдельные URL, self-canonical и обычные HTML-ссылки.

[Google о фасетной навигации](https://developers.google.com/crawling/docs/faceted-navigation)

## Sitemap и robots

- Отдельные sitemap для товаров, категорий, услуг, материалов и изображений.
- В sitemap только canonical URL с ответом 200.
- Закрыть admin, внутренний поиск и технические параметры.
- Не блокировать CSS и JavaScript.
- Для Яндекса использовать Clean-param для UTM, сортировки и режима отображения.

## Перенос

1. Выгрузить URL из Яндекс Вебмастера, Search Console, Метрики, sitemap, логов и WordPress.
2. По возможности сохранить существующий формат /product/{slug}/.
3. Создать таблицу старый URL → новый URL → причина → статус.
4. Использовать прямые 301 без цепочек.
5. Удаленный товар вести на подтвержденную замену или близкую категорию; без аналога отдавать 404/410.
6. Не направлять все старые URL на главную.
7. Проверить status, canonical, robots, sitemap, links и schema на staging.
8. Хранить редиректы минимум год, предпочтительно постоянно.

- [Google о переносе URL](https://developers.google.com/search/docs/crawling-indexing/site-move-with-url-changes)
- [Яндекс об изменении структуры](https://yandex.ru/support/webmaster/ru/recommendations/changing-site-structure)

## Измерение

Сравнить 28 дней до запуска и 28 дней после, затем проверять еженедельно три месяца:

- индексируемые URL;
- клики, показы и позиции по кластерам;
- 404/5xx и canonical-конфликты;
- органические запросы КП;
- звонки и скачивания документов;
- использование калькулятора;
- долю небрендового трафика.
