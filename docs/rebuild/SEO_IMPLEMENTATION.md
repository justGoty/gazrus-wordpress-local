# SEO-реализация Gazrus

Статус: техническая спецификация для Next.js App Router от 4 августа 2026 года.

Документ переводит решения из [SEO_ARCHITECTURE.md](SEO_ARCHITECTURE.md) в проверяемые требования к текущему приложению `web/`. Он не разрешает выдумывать цены, наличие, сроки, характеристики, отзывы, рейтинг, дилерский статус или сведения об организации.

## 1. Приоритеты

- **P0** — обязательное до открытия production для индексирования. Невыполненный пункт блокирует SEO-запуск соответствующей страницы.
- **P1** — развитие после P0, инвентаризации каталога и подтверждения спроса. P1 не должен усложнять MVP или создавать пустые посадочные страницы.

### P0

| Область | Результат |
|---|---|
| URL | Один стабильный canonical для главной, каталога, трех категорий и каждого опубликованного товара |
| Metadata | Уникальные `title`, `description`, canonical и robots для всех индексируемых страниц |
| Open Graph | Корректный предпросмотр главной, каталога, категорий и товаров |
| Индексация | Фильтры, поиск, preview, draft и служебные страницы не индексируются |
| Robots и sitemap | Доступные с кодом 200 файлы `/robots.txt` и `/sitemap.xml`; в sitemap только индексируемые canonical URL |
| JSON-LD | `Organization` на главной; `BreadcrumbList` на вложенных страницах; `Product` на опубликованном товаре |
| Контент | Шаблоны категорий и товаров заполнены фактическим содержанием без автоматически размноженного SEO-текста |
| Изображения | Содержательные изображения выводятся как `<img>` или `next/image` с проверенным `alt`, а не только как CSS background |
| Перелинковка | Главная, каталог, категории и товары связаны обычными HTML-ссылками; нет сиротских страниц |
| Контроль | Проверены Яндекс Вебмастер, ответы сервера, sitemap, микроразметка и важные URL |

### P1

| Область | Результат |
|---|---|
| Посадочные | `/gases/`, `/brands/`, `/solutions/`, `/industries/` создаются только после проверки спроса, ассортимента и уникального содержания |
| Open Graph | Отдельные изображения 1200×630 для категорий и ключевых товаров либо проверенная динамическая генерация |
| Sitemap | Разделение sitemap по типам страниц при росте каталога; отдельный контроль изображений и дат обновления |
| Product | Добавление `mpn`, `sku`, GTIN и связанных моделей только при наличии подтвержденных значений |
| Обход | IndexNow или другая автоматическая передача измененных URL после стабилизации публикационного процесса |
| Аналитика | Сравнение 28 дней до и после запуска, затем еженедельный контроль три месяца |

## 2. Текущая основа и источники данных

Приложение использует Next.js App Router. Базовый origin уже задан в `web/src/app/layout.tsx`:

```text
https://xn--80aaaalzch0asjh0a0a.xn--p1acf
```

Рабочие источники SEO-данных:

- `web/content/seo/site.json` — origin, название сайта, locale и общий шаблон title;
- `web/content/seo/pages.json` — фиксированные страницы, индексация и sitemap;
- `web/content/seo/templates.json` — динамические типы страниц;
- `web/content/catalog/products/*.json` — факты и metadata конкретных товаров;
- `web/content/catalog/redirects.json` — прямые legacy-редиректы.

Запись фиксированной страницы включается в sitemap только если одновременно выполнены условия:

```text
implementation = implemented
seoStatus = ready
indexing = index
sitemap = true
HTTP status = 200
canonical = self
```

Товар включается только при `status=published`, успешной проверке `ProductSchema`, наличии `verifiedAt`, изображения, источника, уникальных metadata и ответа 200.

### Текущее состояние реализации

На 4 августа 2026 года в рабочем дереве подготовлены SEO-data contract, metadata builder, чистые category routes, `sitemap.ts`, production `public/robots.txt`, Organization на главной и Product/BreadcrumbList на товаре. Product содержит пользовательское название категории и подтвержденные `additionalProperty`, а галерея выводит товарные изображения через `next/image`.

До приемки P0 остаются эксплуатационные проверки:

- категории имеют `seoStatus=draft` и правильно не индексируются или не попадают в sitemap до утверждения контента;
- query-варианты доступны для обхода, чтобы робот получил серверный `noindex` и canonical; интерфейс не создает обычные ссылки на комбинации фильтров;
- robots, sitemap, canonical, OG и JSON-LD считаются готовыми только после production build и проверки фактического серверного HTML.

## 3. URL и индексация

Формат production URL — HTTPS, без `www`, без завершающего слеша. Канонический origin хранится в одном месте и не собирается из заголовка входящего запроса.

| Страница | Canonical | Индексация | Приоритет |
|---|---|---|---|
| Главная | `/` | `index, follow` | P0 |
| Общий каталог | `/catalog` | `index, follow` | P0 |
| Стационарные | `/catalog/stationary` | `index, follow` после готовности страницы | P0 |
| Портативные | `/catalog/portable` | `index, follow` после готовности страницы | P0 |
| Сенсоры | `/catalog/sensors` | `index, follow` после готовности страницы | P0 |
| Товар | `/catalog/{category}/{slug}` | `index, follow` только для `published` | P0 |
| Фильтры | `/catalog?{filters}` или query у категории | `noindex, follow` | P0 |
| Модификация товара в query | canonical на базовый товар, `noindex, follow` | P0 |
| Внутренний поиск | `/search?query=...` | `noindex, follow` | P0 |
| Preview, draft, thank-you | собственный URL, `noindex, nofollow` | P0 |
| Несуществующая страница | 404 или 410, без sitemap | P0 |
| Пагинация | self-canonical для непустой страницы | P1 |

Главная должна вести на чистые URL трех категорий, а не на `/catalog?category=...`. До появления отдельной страницы категории query-вариант не становится SEO-посадочной.

Фильтры `gas`, `brand`, `application`, `range`, `sensor`, `channels`, `sampling`, `ex`, `ip`, `interface` меняют выдачу, поэтому их нельзя объявлять незначащими через `Clean-param`. Утвержденная посадочная по газу, бренду или задаче получает отдельный чистый URL только в P1.

## 4. Metadata в App Router

### Размещение

- Общие `metadataBase`, title template, locale и fallback description задаются в `web/src/app/layout.tsx` или через единый builder.
- Фиксированные страницы экспортируют `metadata` либо вызывают общий builder.
- Товарная страница использует `generateMetadata`, потому что данные зависят от `category` и `slug`.
- `metadata` и `generateMetadata` используются только в Server Components.
- В одном route segment нельзя одновременно экспортировать `metadata` и `generateMetadata`.
- При задании вложенного `openGraph` нужно передавать объект полностью: Metadata API объединяет вложенные поля неглубоко.

Целевые точки App Router:

```text
web/src/app/layout.tsx
web/src/app/page.tsx
web/src/app/catalog/page.tsx
web/src/app/catalog/[category]/page.tsx
web/src/app/catalog/[category]/[slug]/page.tsx
web/src/app/sitemap.ts
web/public/robots.txt, metadata file или эквивалентный route handler
```

### Title

Правила:

1. В записи страницы хранится смысловая часть без повторения `| Газоанализатор.рус`.
2. Общий шаблон `%s | Газоанализатор.рус` добавляет название сайта один раз.
3. Главная может использовать абсолютный title, если название сайта уже включено.
4. Модель, уже содержащая бренд, не получает бренд повторно: `СТА-КД1`, а не `СТА СТА-КД1`.
5. Title описывает фактическую страницу и не перечисляет все фильтры или города.
6. Практический ориентир — примерно 45–65 знаков до суффикса, но смысл важнее механического лимита.

Шаблоны:

| Тип | Значение до общего суффикса |
|---|---|
| Главная | `Промышленные газоанализаторы — подбор и поставка` |
| Каталог | `Каталог газоанализаторов и сенсоров` |
| Стационарные | `Стационарные газоанализаторы и системы контроля загазованности` |
| Портативные | `Портативные газоанализаторы для промышленной безопасности` |
| Сенсоры | `Сенсоры для газоанализаторов — подбор по совместимости` |
| Товар | `{model} — {productType}`; бренд добавляется только если его нет в модели |

### Description

- Уникально описывает назначение страницы, проверенные отличия и следующее действие.
- Не дублирует title дословно и не обещает позицию в поиске.
- Не содержит выдуманную цену, наличие, срок, поверку или дилерский статус.
- Для товара строится только из опубликованных полей и обычно занимает 120–180 знаков без искусственного добивания длины.
- Для категории называет тип оборудования и реальные критерии выбора, а не список всех ключевых слов.

Шаблоны:

```text
Категория:
{categoryName}: подбор по {3-4 verified criteria}. Проверенные характеристики, документы и запрос КП.

Товар:
{productType} {model}: {2-4 verified highlights}. Документы, подбор исполнения и запрос КП без фиктивной цены.
```

### Canonical

- Каждая индексируемая страница имеет absolute self-canonical, собранный через `metadataBase`.
- Canonical не содержит UTM, фильтры, сортировку, режим отображения, якорь или завершающий слеш.
- Товар не меняет canonical при выборе модификации в query.
- Несуществующий slug возвращает 404; canonical на категорию или главную не подставляется.
- Canonical не заменяет `noindex` и не используется для маскировки тысяч фасетных дублей.
- При появлении пагинации каждая непустая страница получает self-canonical; все страницы нельзя сводить к первой.

## 5. Open Graph

P0-набор для индексируемой страницы:

```text
og:type = website
og:locale = ru_RU
og:site_name = Газоанализатор.рус
og:url = absolute canonical
og:title = полный title с названием сайта один раз
og:description = description страницы
og:image = абсолютный URL проверенного изображения
og:image:alt = содержательное описание изображения
```

Также задается Twitter Card `summary_large_image`, если есть подходящее изображение, иначе `summary`.

Правила изображений:

- предпочтительный формат предпросмотра — 1200×630;
- URL отвечает 200 без авторизации и редиректов;
- товар использует реальную фотографию модели или специально подготовленную OG-композицию без изменения конструкции;
- категория использует утвержденную сцену соответствующего типа оборудования;
- нельзя указывать размеры изображения, пока они не подтверждены фактическим файлом;
- fallback задается на уровне сайта, но не должен подменять реальное фото товара при его наличии.

## 6. Текущая карточка СТА-КД1

Канонический URL:

```text
https://xn--80aaaalzch0asjh0a0a.xn--p1acf/catalog/stationary/sta-kd1
```

Целевые metadata:

```text
seo.title:
СТА-КД1 — стационарный газоанализатор

Итоговый <title> после layout template:
СТА-КД1 — стационарный газоанализатор | Газоанализатор.рус

seo.description:
Поставка газоанализатора СТА-КД1: 1 канал, IP67, взрывозащита, 4–20 мА, HART и RS-485. Подбор сенсора и диапазона, запрос КП.
```

В текущем `sta-kd1.json` значение `seo.title` уже нормализовано и не содержит суффикс сайта. Это обязательное состояние: `| Газрус` или `| Газоанализатор.рус` нельзя повторно добавлять в товарные данные, потому что общий layout template сформирует двойной бренд.

Разрешенные факты для metadata и JSON-LD:

- модель `СТА-КД1`, бренд `СТА`;
- стационарный одноканальный газоанализатор;
- IP67;
- маркировка взрывозащиты `1Ex db IIC T4 Gb X`;
- 4–20 мА, HART и RS-485/Modbus RTU;
- Госреестр СИ № 96393-25;
- опубликованные газы и проверенные документы;
- реальные изображения из `/images/products/sta-kd1/`.

Поле `ranges` сейчас пустое. Поэтому нельзя добавлять в title, description, видимый текст или JSON-LD конкретные диапазоны измерений до их подтвержденного заполнения.

Для OG используется `sta-kd1-front.webp`, если фактические размеры и композиция подходят для предпросмотра. Иначе применяется проверенный category fallback до подготовки отдельного OG-изображения.

## 7. JSON-LD

JSON-LD рендерится сервером в `<script type="application/ld+json">`. Перед вставкой результат `JSON.stringify` обязательно экранирует символ `<` как `\u003c`. Значения берутся из тех же данных, что видны пользователю.

Допустим один script с `@graph` или несколько scripts без дублирующих сущностей. Для стабильных связей используются абсолютные `@id`.

### Organization

P0: один подтвержденный узел на главной странице либо в общем layout.

```json
{
  "@context": "https://schema.org",
  "@type": "Organization",
  "@id": "https://xn--80aaaalzch0asjh0a0a.xn--p1acf/#organization",
  "name": "Газоанализатор.рус",
  "url": "https://xn--80aaaalzch0asjh0a0a.xn--p1acf/",
  "email": "mailto:info@prscom.ru"
}
```

`legalName`, адрес, телефон, логотип, реквизиты и `sameAs` добавляются только после подтверждения. Название сайта нельзя автоматически выдавать за юридическое наименование компании.

### BreadcrumbList

P0 для категорий и товаров. Видимые breadcrumbs и JSON-LD должны описывать одну и ту же иерархию.

Пример СТА-КД1:

```json
{
  "@context": "https://schema.org",
  "@type": "BreadcrumbList",
  "@id": "https://xn--80aaaalzch0asjh0a0a.xn--p1acf/catalog/stationary/sta-kd1#breadcrumbs",
  "itemListElement": [
    {
      "@type": "ListItem",
      "position": 1,
      "name": "Главная",
      "item": "https://xn--80aaaalzch0asjh0a0a.xn--p1acf/"
    },
    {
      "@type": "ListItem",
      "position": 2,
      "name": "Каталог",
      "item": "https://xn--80aaaalzch0asjh0a0a.xn--p1acf/catalog"
    },
    {
      "@type": "ListItem",
      "position": 3,
      "name": "Стационарные газоанализаторы",
      "item": "https://xn--80aaaalzch0asjh0a0a.xn--p1acf/catalog/stationary"
    },
    {
      "@type": "ListItem",
      "position": 4,
      "name": "СТА-КД1",
      "item": "https://xn--80aaaalzch0asjh0a0a.xn--p1acf/catalog/stationary/sta-kd1"
    }
  ]
}
```

Категория включается в breadcrumbs товара только после появления доступной страницы `/catalog/{category}`. Нельзя размечать ссылку на несуществующий URL.

### Product

P0 для опубликованной товарной страницы. Текущая коммерческая модель не имеет публичной цены, поэтому `Offer` и `AggregateOffer` запрещены.

```json
{
  "@context": "https://schema.org",
  "@type": "Product",
  "@id": "https://xn--80aaaalzch0asjh0a0a.xn--p1acf/catalog/stationary/sta-kd1#product",
  "url": "https://xn--80aaaalzch0asjh0a0a.xn--p1acf/catalog/stationary/sta-kd1",
  "name": "Стационарный газоанализатор СТА-КД1",
  "model": "СТА-КД1",
  "description": "Одноканальный взрывозащищенный газоанализатор для непрерывного контроля одного выбранного компонента в воздухе рабочей зоны и технологических средах. Показывает результат на встроенном дисплее и передает данные в систему.",
  "brand": {
    "@type": "Brand",
    "name": "СТА"
  },
  "category": "Стационарные газоанализаторы",
  "image": [
    "https://xn--80aaaalzch0asjh0a0a.xn--p1acf/images/products/sta-kd1/sta-kd1-front.webp",
    "https://xn--80aaaalzch0asjh0a0a.xn--p1acf/images/products/sta-kd1/sta-kd1-angle.webp"
  ],
  "additionalProperty": [
    {
      "@type": "PropertyValue",
      "name": "Измерительных каналов",
      "value": "1"
    },
    {
      "@type": "PropertyValue",
      "name": "Степень защиты",
      "value": "IP67"
    },
    {
      "@type": "PropertyValue",
      "name": "Взрывозащита",
      "value": "1Ex db IIC T4 Gb X"
    }
  ]
}
```

Правила Product:

- `name`, `description`, `image`, `brand`, `model`, `category` и свойства совпадают с видимой карточкой;
- относительные URL изображений превращаются в абсолютные;
- UUID товара не публикуется как `sku`;
- `sku`, `mpn` и GTIN добавляются только из официального источника;
- `manufacturer` не дублирует бренд без подтверждения юридического производителя;
- пустые диапазоны, модификации и характеристики не размечаются;
- `Offer`, `price`, `priceCurrency`, `availability`, `review` и `aggregateRating` отсутствуют до появления реальных видимых данных;
- предупреждение Яндекса о невозможности товарного расширенного сниппета без `Offer` допустимо и не исправляется фиктивной ценой.

## 8. Шаблон категории

Обязательная P0-структура `/catalog/{category}`:

1. Уникальные title, description, canonical, H1 и OG.
2. Короткое введение: что входит в категорию и по каким параметрам выбирать.
3. Серверный список опубликованных товаров с обычными ссылками на карточки.
4. Категорийные фильтры из `FILTER_MATRIX.md`; query-состояния получают `noindex, follow`.
5. Три-четыре главных критерия выбора без длинного универсального SEO-текста.
6. Ссылки на подтвержденные документы, решения, газы и услуги, если соответствующие страницы существуют.
7. Понятный пустой результат фильтра без создания индексируемой страницы.
8. `BreadcrumbList` и, при необходимости в P1, `ItemList` только для реально показанных товаров.

Категории не смешиваются:

- стационарные: каналы/точки, Ex/IP, способ отбора, интерфейсы;
- портативные: газы, каналы, отбор пробы, сигнализация, автономность;
- сенсоры: совместимость, газ, диапазон, принцип, форм-фактор и интерфейс.

## 9. Шаблон товара

Обязательная P0-структура `/catalog/{category}/{slug}`:

1. Breadcrumbs с рабочими HTML-ссылками.
2. Реальная галерея изображений.
3. Бренд, модель, H1 и краткое назначение.
4. Проверенные газы и три-пять ключевых параметров категории.
5. Коммерческий статус «По запросу» и одно главное действие «Запросить КП».
6. Применение и ограничения.
7. Диапазоны только из структурированного массива `ranges`.
8. Характеристики по смысловым группам.
9. Модификации без смешивания параметров разных исполнений.
10. Проверенные документы.
11. Связанные категория, бренд, газы, решения и подходящие товары только при наличии соответствующих страниц.
12. Product и BreadcrumbList JSON-LD.

Страница не публикуется и не включается в sitemap, если модель не идентифицирована, обязательные факты не подтверждены, нет реального изображения, источника или уникальных metadata.

## 10. Alt и изображения

- Основное изображение товара выводится как `<img>` или `next/image`; CSS background допустим только для декора.
- `alt` описывает тип, модель и конкретный ракурс или содержание изображения.
- Изображения одной галереи имеют разные alt по фактическому содержанию.
- Декоративные полосы, фоны и разделители получают пустой `alt` либо остаются CSS-декором.
- В alt не перечисляются ключи «купить», «цена», города, газы и характеристики, которых нет на изображении.
- Подпись и соседний текст не должны механически повторять alt.
- Имя файла стабильно и понятно: `sta-kd1-front.webp`, а не `img-final-2.webp`.
- Удаленное изображение убирается из HTML, JSON-LD, OG и sitemap одновременно.

Принятые alt для текущей галереи СТА-КД1:

```text
Стационарный газоанализатор СТА-КД1, вид спереди
Газоанализатор СТА-КД1, вид под углом
Маркировочная табличка газоанализатора СТА-КД1
Газоанализатор СТА-КД1 с монтажными принадлежностями
```

## 11. Перелинковка

P0-граф ссылок:

```text
Главная
  → Каталог
  → Стационарные
  → Портативные
  → Сенсоры

Каталог
  → три чистые категории
  → опубликованные товары

Категория
  → товары категории
  → применимые услуги и документы

Товар
  → категория
  → подтвержденный бренд/газ/решение, если чистая страница существует
  → подходящие товары без блока сравнения в MVP
```

Правила:

- используются обычные `<a href>`/`Link`, доступные в серверном HTML;
- анкор описывает назначение страницы: «Стационарные газоанализаторы», а не «Подробнее» вне контекста;
- индексируемая страница имеет хотя бы одну входящую ссылку из доступной навигации или контента;
- ссылка на фильтр не выдается за SEO-посадочную;
- не создаются массовые однотипные ссылки со всеми комбинациями газа, бренда и задачи;
- breadcrumbs, карточка и sitemap используют один и тот же canonical URL;
- старый URL получает один прямой 301 на наиболее близкий новый URL без цепочки.

## 12. Robots.txt

Production robots должен:

- разрешать главную, каталог, категории, товары, изображения, CSS и JavaScript;
- закрывать `/api/` от обхода;
- оставлять query-варианты доступными, пока удаление из индекса опирается на серверный `noindex`;
- не закрывать параметр пагинации существующих непустых страниц;
- содержать абсолютную ссылку на sitemap;
- использовать `Clean-param` только для параметров, не меняющих содержание страницы.

Пример логики:

```text
User-agent: *
Allow: /
Disallow: /api/

User-agent: Yandex
Allow: /
Disallow: /api/
Clean-param: utm_source&utm_medium&utm_campaign&utm_term&utm_content&ysclid&yrclid

Sitemap: https://xn--80aaaalzch0asjh0a0a.xn--p1acf/sitemap.xml
```

Выбранная P0-стратегия отдает приоритет корректному удалению дублей: робот может загрузить query-URL и увидеть серверный `noindex`. Новый интерфейс не создает обычные индексируемые ссылки на комбинации фильтров, поэтому для текущего объема каталога это не формирует значимое пространство обхода. Если после расширения каталога crawl-нагрузка станет заметной, отдельные фасеты можно закрыть через `Disallow` только после удаления уже известных URL из индекса.

Если нужен `Clean-param`, простой типизированный `MetadataRoute.Robots` недостаточен: допустимы текущий статический `web/public/robots.txt`, metadata file с подходящим форматом или route handler, который возвращает проверенный текст. Правила для `User-agent: Yandex` дублируют нужные ограничения, а не рассчитывают на секцию `User-agent: *`.

Staging защищается авторизацией и дополнительно отдает `X-Robots-Tag: noindex, nofollow`. Одного `robots.txt` недостаточно для гарантированного удаления уже известного URL из поиска.

## 13. Sitemap

Для текущего объема достаточно одного `web/src/app/sitemap.ts` с типом `MetadataRoute.Sitemap`.

P0-правила:

- только абсолютные canonical URL;
- только страницы с ответом 200 и разрешенной индексацией;
- только `published`-товары;
- никаких query, фильтров, preview, draft, redirect, 404 или 410;
- `lastModified` товара берется из `updatedAt`, а не из времени каждой сборки;
- изображения товара добавляются абсолютными URL после проверки доступности;
- категория входит в sitemap только после готовности контента и `seoStatus=ready`;
- `/sitemap.xml` отвечает 200, доступен без авторизации и указан в robots.txt.

Нельзя выставлять всем страницам новый `lastModified` при каждом deploy: это делает дату бесполезной для робота.

P1: при росте каталога sitemap делится по типам (`pages`, `categories`, `products`, `knowledge`) или через `generateSitemaps`; sitemap index добавляется в Яндекс Вебмастер.

## 14. Проверка в Яндекс Вебмастере

### До открытия индексации

1. Добавить точный HTTPS-host production и подтвердить права.
2. Проверить главное зеркало, HTTPS и отсутствие доступных дублей с `www` или другим host.
3. Инструментом проверки ответа сервера проверить `/`, `/catalog`, три категории, СТА-КД1, `/robots.txt` и `/sitemap.xml`.
4. В валидаторе robots проверить доступность индексируемых URL и запрет служебных путей.
5. В валидаторе sitemap проверить файл по URL, затем добавить его в «Индексирование → Файлы Sitemap».
6. В валидаторе микроразметки проверить `Organization`, `BreadcrumbList`, `Product` и Open Graph.
7. Зафиксировать допустимое предупреждение Product без Offer; не добавлять цену `0`, фиктивную валюту или наличие.
8. Проверить canonical и robots в исходном серверном HTML, а не только после клиентского JavaScript.
9. Добавить главную, каталог, категории и СТА-КД1 в список важных страниц.

### После запуска

1. Отправить главную, каталог, три категории и СТА-КД1 через «Переобход страниц».
2. Sitemap не отправлять через переобход: он управляется в разделе файлов Sitemap.
3. Проверить «Страницы в поиске», «Исключенные страницы», диагностику и статистику обхода.
4. Отдельно проверить дубли с UTM, фильтрами, сортировкой и устаревшими WordPress URL.
5. Контролировать 404/5xx, canonical-конфликты, страницы без входящих ссылок и расхождения sitemap с реальными ответами.
6. Через 28 дней сравнить показы, клики, запросы, индексируемые URL и органические запросы КП с периодом до запуска.

## 15. Правило без переспама

1. Одна страница отвечает одному основному поисковому намерению.
2. Нет обязательной плотности ключевых слов; текст оценивается по ясности, фактам и пользе.
3. Главная фраза естественно используется в title, H1 и первом смысловом блоке, но не повторяется в каждом подзаголовке.
4. Название модели пишется так, как в официальном источнике; варианты написания добавляются только когда помогают пользователю.
5. Нельзя перечислять города, газы, отрасли и характеристики, если страница не дает по ним отдельной полезной информации.
6. Слова «купить» и «цена» не сопровождаются фиктивной стоимостью: страница честно объясняет запрос КП и зависимость комплектации от исполнения.
7. Alt, anchors, title, description и JSON-LD не используются как места для повторения одного списка ключей.
8. Автоматически созданная страница фильтра не индексируется. Чистая посадочная создается только при спросе, устойчивом ассортименте и уникальном содержании.
9. Нельзя копировать один абзац между категориями и товарами с заменой модели или газа.
10. Неподтвержденный факт удаляется или остается внутренней задачей, а не смягчается рекламной формулировкой.

## 16. Критерии приемки

### P0 готово, если

- production host и canonical совпадают на всех проверенных страницах;
- title содержит название сайта один раз;
- title, description и H1 уникальны и соответствуют видимому содержанию;
- главная ведет на три чистые категории;
- фильтры и поиск имеют `noindex, follow` и отсутствуют в sitemap;
- primary product image является реальным HTML-изображением с alt;
- OG URL и изображения абсолютные и отвечают 200;
- Organization, BreadcrumbList и Product проходят синтаксическую проверку;
- Product СТА-КД1 не содержит Offer, фиктивной цены, наличия, диапазонов или рейтинга;
- robots.txt и sitemap.xml отвечают 200 и проходят валидаторы Яндекса;
- в sitemap нет draft, query, redirect, 404 и noindex URL;
- новые страницы доступны по обычным внутренним ссылкам;
- staging закрыт от индексации;
- сборка проверяет SEO-данные и не публикует невалидную запись.

### P1 готово, если

- спрос и семантика подтверждены данными, а не предположением;
- каждая новая посадочная имеет самостоятельный интент и уникальное экспертное содержание;
- sitemap масштабирован без дублей;
- новые идентификаторы Product подтверждены первичным источником;
- обновленные страницы автоматически передаются на обход и контролируются после публикации.
